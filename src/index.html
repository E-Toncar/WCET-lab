SWEET Lab

Abstract execution on a small C-like language, lowered to ALF-style code.

  • Loop bounds per entry and per program run
  • Infeasible code and infeasible path pairs
  • State splitting, merging and path explosion
  • Why analysis without widening may not terminate

T-CREST project · Patmos and platin

T-CREST Lab

A cycle-level Patmos-style simulator next to a platin-style static WCET analysis.

  • Delayed branches, predication and dual issue
  • Method cache, stack cache, scratchpad, data cache
  • Per-block costs and the IPET linear program
  • Measured time vs. bound, and unsafe flow facts

A suggested order

  1. SWEET Lab, "Input-dependent loop": read the AE trace and see where the state splits.
  2. SWEET Lab, "Triangular nested loops": compare the per-entry and per-run bounds.
  3. SWEET Lab, "Path explosion": switch state merging on and off.
  4. T-CREST Lab, "Scratchpad vs. data cache": find where the overestimate comes from in the block table.
  5. T-CREST Lab, "Data-dependent branch" then "Single-path code": see the bound become exact.
  6. T-CREST Lab, "Method and stack cache": lower the cache sizes and watch the costs move onto call edges.
  7. T-CREST Lab, "A wrong flow fact": what happens when the flow analysis is wrong.
These labs are teaching models, not the original tools. See the "How it works" tab in each lab for what is simplified and where to find SWEET and T-CREST.
